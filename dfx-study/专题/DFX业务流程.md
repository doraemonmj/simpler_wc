# DFX 业务流程：模块与一次运行

这是一份约 8 分钟的专题串讲提纲。主线是：**一次运行怎样启用 DFX，各模块在什么位置提供信息，记录怎样变成可查看的结果？**

## 一张图看全程

~~~text
本轮运行配置：选择采集能力与输出位置
  ↓
运行时产生记录
  ├─ 阶段耗时：STRACE / Device phases → 日志或阶段记录
  ├─ 任务、计数、参数、资源：各模块 → 公共采集通道 → Host Collector
  └─ 任务依赖：dep_gen → 设备侧记录后收集，或 Host 构图时直接记录
  ↓
运行结束：收齐尾部记录、核对完整性、导出本轮产物
  ↓
仓库工具：关联记录、转换时间、计算指标
  ↓
阶段耗时 / 任务时间线 / 依赖图 / 计数与资源报告 / 参数内容
  ↓
浏览器、Perfetto 或外部插件查看
~~~

这条链路分成三件事：**运行时留下事实，Host 保存本轮证据，离线工具把证据变成可读结果。** 查看器负责展示已有结果。不同能力产生的记录并不都走同一条采集通道，但最后都归到这次运行的证据中。

## 模块各自回答什么

- **STRACE / Device phases：** 整轮和主要阶段花了多久，适合先判断问题落在哪一段。
- **Chip Swimlane：** 任务何时下发、开始和结束，适合看执行时间与任务之间的空档。
- **dep_gen：** 任务之间有哪些依赖，帮助解释任务为何必须等待。
- **PMU：** 任务执行时的硬件计数，为性能分析补充设备侧指标。
- **Args Dump：** 保存所选任务的参数证据，供结果检查或后续重放。
- **Scope Stats：** 记录资源变化与高水位，帮助定位容量和积压问题。
- **Core Swimlane：** 在运行产物的基础上，对单个任务做隔离重放，进一步查看核内执行；它属于后续分析环节。

这些能力回答不同问题。一次运行通常按目的选择其中几项；阶段、任务、依赖、资源和参数等证据可以在落盘后关联。

## 一次运行怎样走完

1. **配置本轮。** 运行方确定需要开启的 DFX 能力和产物位置。开关属于这次运行，决定后续哪些记录会出现。
2. **运行中记录。** Host、AICPU 和 AICore 在各自能观察到事实的位置留下记录。阶段类信息可直接写日志或在结束后读回；持续产生的任务、计数、参数和资源记录经公共采集通道交给 Host。依赖记录按运行时构图方式走设备侧或 Host 侧路径。
3. **收尾并导出。** 运行结束后停止产生新记录，收齐尾部数据，核对采集与丢弃情况，再完成本轮原始产物。这样后续分析才知道记录属于哪次运行、是否完整。
4. **离线处理。** 仓库工具把原始记录关联到任务、换算时间或汇总指标，得到时间线、依赖图和统计结果。原始记录与最终视图是两个阶段。
5. **查看结果。** 使用日志、仓库生成的报告或外部查看器观察结果。图表呈现证据；解释“为什么慢或为什么等”时，还要结合相应的依赖、资源或参数信息。

## 串讲顺序

- **前 2 分钟：** 先展示总链路，说明 DFX 从单次运行配置开始，结果在离线处理后才适合阅读。
- **接下来的 3 分钟：** 沿一次运行讲记录、Host 收集和结束时的产物核对；用上面的模块列表说明每类证据回答什么。
- **最后 3 分钟：** 以“运行变慢”为例：先看阶段耗时，再看任务时间线；若出现空档，再结合依赖与资源信息解释。回到总链路，说明为什么单张图不能独自给出根因。
