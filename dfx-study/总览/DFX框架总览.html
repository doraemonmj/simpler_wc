Chip Swimlane 等级

Level 1 采 AICore 时间；2 增加 dispatch/finish；3 增加 scheduler phases；4 再增加 orchestrator phases。同等级的 Level 1 或 2 运行在满足保留采集条件时可以接续下发，共用设备队列。

依赖图保持离线合并

Swimlane 热路径不记录依赖箭头。转换工具按 task id 将时间数据与 deps.json 合并。

Analysis & Visualization

从产物到结论：两种处理方式

先核对运行归属、完整性与时钟，再区分结果由仓库工具生成，还是交给外部查看器或插件处理。

方式一：仓库内工具

simpler_setup.tools 计算阶段耗时、调度开销与关键路径，也做格式转换。deps_viewer 和 scope_stats_plot 还能直接生成独立 HTML，浏览器即可打开。

方式二：外部查看器或插件

swimlane_converter 导出兼容 trace 后，可用 Perfetto 看时间线；core_swimlane 的核内 trace 可用 MindStudio Insight 或 Perfetto 查看。外部工具负责交互浏览或自己的进一步分析。

浏览器只是打开仓库生成的 HTML；Perfetto 和 Insight 是独立查看器。.claude/skills/dfx-analyze 是使用指引，不是另一个分析引擎。

解释结果时仍须核对记录完整性、任务关联和时钟域；外部插件若计算新指标，应说明自己的口径。

Layers

六个稳定层次

公共机制集中在 src/common/platform，具体能力只保留领域差异。

01

用户入口

SceneTest CLI 或 Python CallConfig 选择能力、等级与输出目录。

02

运行配置

DfxRunConfig 固化单次运行快照，隔离流水并发中的前后运行。

03

Host 控制层

ProfilerBase 管理 drain、replenish、collector 线程和 start/stop。

04

Host 数据层

BufferPoolManager 管理 SPSC 队列、地址映射和缓冲所有权。

05

设备算法层

DeviceProfilerEngine 统一 ready/free 等待、发布与换缓冲。

06

领域与分析层

具体 Collector 解释记录；simpler_setup.tools 生成可读结果。

Lifecycle

一次运行的四段生命周期

默认模式按管理线程、Collector 的顺序完成最终 drain；保留模式按 run epoch 封住每轮边界。

1

解析与预置

校验 output_prefix，构造 DfxRunConfig，分配 run epoch，预置设备缓冲和 free queue。

2

设备侧生产

AICPU/AICore 写当前缓冲；满缓冲进入 ready queue，并领取替换缓冲继续采集。

3

Host 流式消费

drain 线程复制或映射数据；collector 解释记录；replenish 回收并补足缓冲。

4

封口与发布

默认模式同步完成最终 drain 与导出；保留模式先封住本轮边界，再由后台整理和发布文件。

背压策略

按 lane 阻塞等待，正常压力下不主动丢记录；Host 连续 30 秒无进展才触发保护性 drop。

后台发布

collect_across_runs=True 可让文件发布与下一次设备运行重叠；Worker.flush_diagnostics() 是发布与完整性的确认屏障。仅启用 Chip Swimlane、两次运行同为 Level 1 或同为 Level 2、使用不同 pipeline slot，且 Collector 形状不变并有可用的保留桶时，后继运行可接续下发。每轮按 run epoch 归属记录和元数据。

Platforms

a2a3 与 a5 的统一面和差异点

对用户保持同一开关和产物格式，传输实现按硬件能力分化。

a2a3

  • 通过 Host 注册后的映射内存访问设备缓冲。
  • Host 可以解析设备指针到映射地址。
  • 统一框架直接消费映射后的 payload。
同一框架
同一产物

a5

  • 没有同样的 halHostRegister 路径。
  • 每个设备缓冲配对 Host shadow。
  • 通过 rtMemcpy 拉取 payload，并只回写 Host 修改的字段。

运行时差异

dep_gen 在 TMR 侧主要消费设备 orchestration 记录；HBG 可从 Host 构图直接生成相同 deps.json。

能力边界

Scope Stats 当前面向 TMR 的 ring/scope 模型；其余主体 Collector 跨 runtime 复用。
