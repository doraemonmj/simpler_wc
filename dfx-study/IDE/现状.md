# PyPTO 3.0 IDE 现状

## 范围与版本

这里的目标是 **PyPTO 3.0 的开发与 DFX 产物查看**。PyPTO3 Toolkit 的公开用户文档标记 v1.0.0，本机安装包 `cann-pub.pypto-toolkit-4.0.36` 则是另一个扩展版本号；两者不能直接当作同一提交。旧源码检出 `pypto-tools_pypto3_gitcode` 的扩展版本 `2.0.19` 混有早期 PyPTO3 泳道支持，但缺少本机安装包中的依赖图、IR Trace 和 Memory Map 路由，因此不能代表当前 3.0 能力。

本目录用 3.0 用户文档界定产品功能，用已安装扩展的 `dist/` 代码核对入口和字段。未在 VS Code 中用真实产物做端到端打开验证。

## 模块地图

| 模块 | 主输入 | 当前用途 |
| ---- | ------ | -------- |
| [Chip Swimlane](模块/Chip-Swimlane.md) | `chip_swimlane_records.json` | 看 AICore 执行、AICPU 调度、Orchestrator 阶段、任务详情与性能分析 |
| [依赖图](模块/依赖图与性能.md) | `deps.json` | 看任务 DAG、Tensor 参数、依赖边和冗余边 |
| [函数性能表](模块/依赖图与性能.md) | `name_map*.json` + 同目录泳道 | 按 Func ID 汇总次数与执行耗时 |
| [关键路径](模块/依赖图与性能.md) | `CPM_static*.json`、`CPM_observed*.json` | 在泳道中高亮已有结果；本机安装包还提供调用 simpler 工具生成报告的入口 |
| [IR Pass Trace](模块/IR-Pass与内存复用.md) | `passes_dump*` 中连续编号的 `.py` 快照 | 比较 Pass 前后 Python IR |
| [Memory Map](模块/IR-Pass与内存复用.md) | `*after_AllocateMemoryAddr.py` | 根据 IR 中的地址与生命周期展示片上内存复用 |
| [Serving 泳道](模块/Serving泳道.md) | `serving-strace-swimlane.json` | 看 Serving 任务时序及 WorkerProcess 统计 |

主线是从 VS Code 资源管理器对文件或 `passes_dump*` 目录执行打开命令。PyPTO 3.0 的 Chip Swimlane **直接读取原始 `chip_swimlane_records.json`**；`merged_swimlane.json` 是另一种已转换 trace，主要用于 Perfetto 等查看器。当前安装包在同目录同时存在两者时，还会优先把 `merged_swimlane.json` 的预览切到对应的 chip 原始文件。详细入口见[文件打开与版本边界](模块/文件打开与版本边界.md)。

## 与 simpler 当前产物的关系

```text
simpler 运行/编译产物
├─ dfx_outputs/chip_swimlane_records.json ──→ IDE Chip Swimlane
│  ├─ deps.json + name_map*.json ────────────→ 依赖/名称增强
│  └─ CPM_static*.json / CPM_observed*.json ─→ 路径高亮
├─ dfx_outputs/deps.json ────────────────────→ IDE 依赖图
├─ dfx_outputs/name_map*.json + chip 记录 ───→ 函数性能表
└─ passes_dump*/NN_<Pass>.py ────────────────→ IR Trace / Memory Map
```

**兼容边界：** simpler 当前 `chip_swimlane_records.json` 的 `aicore_tasks` 已带 `run_epoch`，Scheduler 数据是 `scheduler_tasks`、`scheduler_records`。本机 4.0.36 扩展的原始记录转换器识别 `aicore_tasks`，但代码仍主要读取旧字段 `aicpu_tasks`、`aicpu_scheduler_phases`，并未按 `run_epoch` 关联。因此“能识别并打开文件”不等于当前 simpler 全部调度泳道和多轮任务归属都能正确展示。具体见[Chip Swimlane](模块/Chip-Swimlane.md)。

公开文档 v1.0.0 说插件只读取已有 CPM；本机 4.0.36 的 `dist/services/critical-path/index.js` 还可调用 `simpler_setup.tools.critical_path` 生成报告和 CPM 文件。这是版本差异，不应把本机入口回写成 v1.0.0 的功能承诺。
