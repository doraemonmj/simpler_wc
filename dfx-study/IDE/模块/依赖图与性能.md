# 依赖图、函数性能与关键路径

## 任务依赖图

`deps.json` 可独立打开。`dist/core/deps-graph/depsGraphBuilder.js` 读取 `tasks[]`、`edges[]`、`tensors[]`，建立任务节点、参数和有向边；同目录最新的 `name_map*.json` 可补函数名。界面提供 Full、Reduced、Omitted 等边模式以及前后驱高亮。输入字段见[数据结构](../数据结构.md#depsjson-任务图)。

节点的 `kernel_ids` 区分 AIC、AIV、MIX、ALLOC，并在芯片泳道中帮助恢复 Func ID；`early_dispatch` 是依赖描述中的标记，不等于本次运行真的提前下发成功。冗余边是图分析结果，阅读时需先核对原始边的 `source` 和 Tensor 关系。

## 函数性能表

直接打开 `name_map*.json` 会进入 `nameMapTable`。`dist/view/servers/name-map-server.js` 读取 `callable_id_to_name`，再寻找同目录 `chip_swimlane_records.json` 等泳道文件；没有泳道数据会报错。表格按 Func ID 汇总 Count、Max/Min/Avg Duration，并从 Kernel 时长中扣除 Setup。因此 `name_map*.json` 是名称映射，不是独立的耗时来源。

## 关键路径与分析

`CPM_static*.json`、`CPM_observed*.json` 是同目录泳道的辅助文件。`dist/handler/swimGraphMsgHandler.js::getCriticalPathData` 从其中的 `traceEvents` 找 Worker 任务，取 `args.taskId` 供高亮。公开用户文档 v1.0.0 描述读取已有 CPM 的功能。

本机安装包 `4.0.36` 另有 `analyzeCriticalPath` 入口，`dist/services/critical-path/index.js` 会调用当前 Python 环境的 `simpler_setup.tools.critical_path`，寻找生成的 `critical_path_report.md` 和 CPM 文件。这一操作依赖可用的 simpler Python 工具及适合分析的原始记录、依赖图和名称映射；本目录没有实际执行该命令。它是较新扩展包的能力，不能据此断言公开 v1.0.0 已提供。
