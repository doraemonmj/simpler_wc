# 文件打开与版本边界

## PyPTO 3.0 的入口

本机安装包的 `package.json` 注册了普通 JSON 打开、`deps.json` 依赖图、`passes_dump*` 目录的 IR Trace，以及 `*after_AllocateMemoryAddr.py` 的 Memory Map 入口。`dist/command/registerCommand.js::openView` 还按文件名识别 `name_map*.json`、`deps.json`，按文件内容识别 `chip_swimlane` / `aicore_tasks`、`tasks` 或 `traceEvents`。`dist/view/routes.js` 有 `swimGraph`、`depsGraph`、`nameMapTable`、`irTrace`、`pyptoStudio` 路由。

| 文件或目录 | 打开后的模块 | 额外条件 |
| ---------- | ------------ | -------- |
| `chip_swimlane_records.json` | Chip Swimlane | 文件内有可识别的 `aicore_tasks` 等记录 |
| `deps.json` | 任务依赖图 | 文件名需精确匹配 |
| `name_map*.json` | 函数性能表 | 同目录须有受支持的泳道文件 |
| `passes_dump*` 目录 | IR Pass Trace | 含 `00_frontend.py` 和连续编号快照 |
| `*after_AllocateMemoryAddr.py` | Memory Map | IR 文本能由解析器识别 |
| `serving-strace-swimlane.json` | Serving 泳道 | 独立的 trace 文件 |

`dist/common/swimlane-file.js` 对 `merged_swimlane*.json` 有特别处理：同目录存在匹配的 `chip_swimlane*.json` 时优先打开后者，避免把 Perfetto 导出误当成 3.0 IDE 的主输入。没有 chip 文件时仍保留已转换 trace 的打开路径。

## 旧版功能放在哪里

旧插件源码检出 `pypto-tools_pypto3_gitcode` 的版本为 `2.0.19`，它的运行结果侧边栏依赖 `rundata.json`，控制流与计算图使用 `program.json` 和图 JSON，泳道图已有 `perf_swimlane.json` / `merged_swimlane.json` 路径。这些属于插件的旧功能脉络；PyPTO 3.0 文档主线以 `dfx_outputs` 和 `passes_dump*` 文件为中心，不要求先构造 `rundata.json`。

本机安装包保留部分旧路由，不能因为路由仍在就把 `program.json`、OpCheck 或 GM 内存格式写成 PyPTO 3.0 DFX 的必需输入。要核对旧功能可回看 [DFX 框架总览第 4 节](../../总览/DFX框架总览.md#4-外部查看插件pypto-tools_pypto3)。
